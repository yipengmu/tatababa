# 塔塔爸爸.ai 个人主页方案 Spec

> 文档状态：Implementation v0.2
>
> 创建日期：2026-08-24；实施更新：2026-08-25
>
> 当前范围：前台个人主页、单管理员内容后台、Vercel 部署配置；正式文案和缺失链接仍待补齐

## 1. 项目概述

### 1.1 项目背景

建立一个以“塔塔爸爸.ai”为个人品牌的主页网站，通过三个与 AI 时代相关的人生维度，系统介绍个人经历、长期内容与自主开发的作品：

1. AI 时代的职场实践；
2. AI 时代的育儿教育；
3. AI 时代的生活智慧。

网站不是简单的链接集合，而应回答三个问题：

- 你是谁；
- 你长期关心和实践什么；
- 访客现在可以阅读、观看或体验什么。

### 1.2 一句话定位

**一个技术人、产品实践者和父亲，在 AI 时代关于工作、教育与生活的长期实验场。**

### 1.3 暂定品牌表达

- 品牌名：`塔塔爸爸.ai`
- 主标题建议：`在 AI 时代，重新学习工作、养育与生活`
- 辅助说明建议：`记录真实经验，分享可复用的方法，也把想法做成能被使用的产品。`
- 品牌人格：真实、务实、有温度、持续动手、不过度包装

以上是信息架构阶段的占位文案，正式开发前可进一步口语化并加入个人经历。

## 2. 核心目标与衡量方式

### 2.1 首要目标

让第一次访问的用户在 30 秒内形成清晰认知：

> “塔塔爸爸是一个既做技术和产品，也认真思考育儿与生活，并持续公开分享成果的人。”

### 2.2 次要目标

- 引导用户进入视频号、公众号和微信文章合集；
- 引导用户体验个人开发的软件和孩子制作的游戏；
- 建立一个可持续更新的个人内容索引，减少内容散落在不同平台的问题；
- 为未来合作、交流或个人品牌传播提供统一入口。

### 2.3 建议指标

首版发布后按月观察：

| 指标 | 定义 | 首版建议目标 |
| --- | --- | --- |
| 三大主题到达率 | 访问者浏览至三个主题区域中的至少一个 | ≥ 60% |
| 内容点击率 | 点击视频号、公众号、文章或系列内容 | ≥ 15% |
| 作品体验点击率 | 点击软件或游戏体验入口 | ≥ 8% |
| 首页有效停留 | 非误触访问的中位停留时长 | ≥ 60 秒 |
| 跳转有效性 | 对外链接可正常访问 | 100% |

指标用于判断内容层级是否有效，不建议把“页面访问量”本身作为首版成功标准。

## 3. 关键产品判断

### 3.1 已确认决策

首页采用“一个人，三个观察切面”的连续叙事。人物认知是全站主线，访客先认识人，再选择感兴趣的内容和作品；“牛马职场、育儿教育、生活智慧”作为三个并列专题呈现，但不脱离人物主线。

建议叙事顺序：

1. 我是谁；
2. 我在职场中如何实践 AI；
3. 我如何和孩子一起理解与创造；
4. 我如何记录长期生活经验；
5. 去看内容、体验作品或关注账号。

### 3.2 批判性问题与风险

#### 问题 A：网站更重要的是“介绍你”还是“给内容导流”？

两种目标会产生不同首页：

- 个人认知优先：首页需要人物介绍、经历和价值观，内容作为证据；
- 内容导流优先：首页需要大量卡片和明确跳转，人物介绍应压缩。

**确认结果：个人认知优先，内容与作品承担证明作用。** 首页第一屏和“关于我”先建立身份与价值观，三个专题随后提供证据和行动入口。

#### 问题 B：“牛马职场”是否适合作为长期一级栏目名？

“牛马职场”有传播力和亲切感，但也可能造成两个问题：

- 对不熟悉你的访客，它容易被理解为纯吐槽内容；
- 当未来加入职业转型、产品方法或合作案例时，栏目语义可能过窄。

**确认结果：** 保留“牛马职场”的传播力，正式一级专题名采用“AI 时代的牛马职场”。栏目内容通过“转型、产品、晋升、工具”避免退化为纯吐槽表达。

#### 问题 C：图 3 与“三大推荐阅读”的含义不一致

图 3 展示的是三组公众号服务栏目：

- 技术转 PD；
- 产品经理；
- 大厂晋升。

每组下面还有多个细分标签，因此它更像“公众号内容导航”，而不是三篇具体的推荐文章。首版应避免把栏目截图直接解释为三篇推荐阅读。

**确认结果：** 图 3 对应公众号中的三个长期专题，不再设计为三篇独立推荐文章：

- 技术转 PD；
- 产品经理；
- 大厂晋升。

当前已创建三个专题入口，其中“大厂晋升”使用已有合集链接，另外两个链接后续从公众号提供或抓取。

## 4. 目标访客

### 4.1 主要访客

| 访客 | 主要诉求 | 应看到的内容 |
| --- | --- | --- |
| 技术人与产品人 | 转型、晋升、AI 工具与实战经验 | 大厂晋升、程序员转型、软件作品 |
| 关注 AI 教育的家长 | 如何陪孩子理解和使用 AI | 育儿内容、孩子做的游戏、亲子共创过程 |
| 已有公众号/视频号读者 | 快速找到系列内容和历史沉淀 | 视频号入口、公众号入口、系列合集 |
| 潜在合作伙伴 | 判断经历、能力与关注方向 | 人物介绍、代表作品、内容成果、联系入口 |

### 4.2 非目标

首版不承担以下任务：

- 做成多人协作或带复杂审核流的完整 CMS；
- 把微信文章全文同步到站内；
- 建立用户注册、评论或社区；
- 做复杂的 AI 对话助手；
- 以广告或付费转化为第一目标。

首版包含供本人使用的轻量内容后台，可以维护人物文案、三个专题、文章系列、软件、游戏、关注入口和发布状态。

## 5. 网站信息架构

首版建议采用单页首页，页面内部使用锚点导航。后续内容量增加后，再把系列内容与作品拆成详情页。

```text
首页 /
├── 首屏：人物定位与主要行动
├── 关于我：简短经历与三个身份
├── 主题一：AI 时代的职场进化
│   ├── 视频号入口
│   ├── 大厂晋升系列
│   ├── 程序员转型系列
│   └── 软件与开放作品
├── 主题二：AI 时代的育儿教育
│   ├── 视频号入口
│   └── 小朋友制作的游戏
├── 主题三：AI 时代的生活智慧
│   ├── 公众号入口
│   ├── 三篇推荐阅读或三大内容专题
│   └── 年度总结合集
└── 页尾：社交入口、联系信息与版权信息
```

### 5.1 顶部导航

- 品牌标识：塔塔爸爸.ai
- 职场
- 育儿
- 生活
- 我的作品
- 关于我
- 主要按钮：`关注 / 找到我`

移动端可收起导航，但三个核心主题应始终容易到达。

## 6. 首页模块方案

### 6.1 首屏 Hero

#### 目标

在第一屏同时建立人物认知和内容预期，不使用泛化的“拥抱 AI、改变未来”类口号。

#### 内容

- 品牌名与头像；
- 主标题；
- 1～2 句个人介绍；
- 三个身份标签，例如：`技术人`、`产品实践者`、`父亲`；
- 主行动：`看看我在做什么`，滚动至三大主题；
- 次行动：`体验我的作品`，滚动至作品卡片。

#### 待补信息

- 真实姓名或希望公开使用的称呼；
- 当前职业/经历的一句话版本；
- 是否公开所在城市、公司经历或联系方式；
- 可用于首页的个人照片，或确认继续使用当前小狗头像作为品牌头像。

### 6.2 关于我

建议使用 80～150 字完成介绍，结构如下：

1. 过去和现在在做什么；
2. 为什么持续记录这三个主题；
3. 读者能从这里获得什么。

不建议在首页放完整履历。若未来确有合作需求，可增加独立“关于我”页面。

### 6.3 主题一：AI 时代的职场进化

#### 模块导语建议

> 从写代码到做产品，从完成任务到建立影响力。记录真实的大厂经验，也探索普通人在 AI 时代如何获得更好的工具、方法和选择。

#### 内容组成

1. **视频号入口**
   - 使用已提供的视频号二维码素材；
   - 显示账号名“塔塔爸爸.ai”；
   - 补充说明：内容类型、更新方向、适合谁看；
   - 桌面端可点击放大二维码，移动端支持长按识别或保存。

2. **大厂晋升系列**
   - 类型：微信文章合集；
   - 已有链接：<https://mp.weixin.qq.com/mp/appmsgalbum?__biz=MzA4ODc0NzgwNg==&action=getalbum&album_id=2105137822998249480&scene=305#wechat_redirect>；
   - 展示信息：系列名、2 句介绍、文章数量（待补）、推荐阅读对象；
   - 行动按钮：`查看完整系列`。

3. **程序员转型系列**
   - 建议定位：从工程师到产品/业务/管理方向的真实经验；
   - 展示形式：3～6 张精选内容卡片 + 完整系列入口；
   - 当前缺少：系列链接、代表文章、摘要和封面。

4. **软件与开放作品**
   - 家谱产品/项目；
   - 口播 App；
   - 其他后续开放软件。

每个作品使用统一卡片，至少包含：

- 产品名称；
- 一句话解决的问题；
- 当前状态：可体验 / 内测 / 开源 / 制作中；
- 1 张界面截图或演示图；
- 体验链接；
- 可选：源码链接、开发背景、技术栈；
- 明确的行动按钮：`立即体验`、`查看介绍` 或 `查看源码`。

### 6.4 主题二：AI 时代的育儿教育

#### 模块导语建议

> 不只教孩子使用 AI，也和孩子一起提问题、做东西、复盘过程。把技术变成创造力，而不是标准答案。

#### 内容组成

1. **视频号入口**
   - 与职场模块可复用同一账号入口；
   - 页面上不重复展示两个完整大二维码，建议此处使用轻量账号卡片，并说明可在视频号查看亲子与 AI 内容；
   - 若未来育儿内容使用独立账号，再拆分入口。

2. **小朋友制作的游戏**
   - 建议按作品而不是按年龄展示；
   - 每个游戏包含：名称、孩子的想法、完成过程、家长参与边界、截图、体验链接；
   - 若使用了 AI，可注明 AI 在其中扮演的角色，例如“构思辅助 / 图片生成 / 编程协作”；
   - 避免公开孩子的学校、班级、真实姓名等敏感信息。

#### 游戏卡片建议字段

| 字段 | 是否必需 | 示例 |
| --- | --- | --- |
| 游戏名称 | 是 | 待补充 |
| 一句话玩法 | 是 | 30 秒内理解怎么玩 |
| 创作者署名 | 否 | 昵称或年龄段，不使用敏感身份信息 |
| 游戏截图 | 是 | 主界面或代表性玩法 |
| 体验链接 | 是 | 可公开访问的 URL |
| 创作故事 | 建议 | 为什么想做、怎么完成 |
| AI 参与方式 | 建议 | 构思、绘图、代码或测试 |

### 6.5 主题三：AI 时代的生活智慧

#### 模块导语建议

> 技术改变工具，生活仍需要长期判断。这里记录选择、成长、家庭和每一年真实发生过的变化。

#### 内容组成

1. **公众号入口**
   - 使用已提供的公众号二维码；
   - 补充公众号名称与内容简介；
   - 桌面端支持点击放大，移动端支持长按识别或保存；
   - 不建议只显示无说明的二维码。

2. **推荐阅读**
   - 默认方案：展示 3 篇最能代表个人价值观的文章；
   - 每篇包含标题、发布日期、50～80 字摘要、封面/视觉、文章链接；
   - 推荐文章应覆盖不同主题，避免三篇都属于职场技巧；
   - 若图 3 实际代表三大专题，则调整为“技术转 PD / 产品经理 / 大厂晋升”三张专题卡。

3. **年度总结合集**
   - 已有链接：<https://mp.weixin.qq.com/mp/appmsgalbum?__biz=MzA4ODc0NzgwNg==&action=getalbum&album_id=1667762019313172483&scene=305#wechat_redirect>；
   - 首版可使用“时间轴 + 合集入口”；
   - 若能提供每年文章的独立链接，可按年份列出标题和一句摘要；
   - 行动按钮：`查看历年总结`。

4. **公众号内容地图（待确认）**
   - 图 3 可转化为站内可读的文字卡片，不建议直接把截图作为主要导航；
   - 已识别的内容如下：

| 大类 | 子栏目 |
| --- | --- |
| 技术转 PD | 安卓转前端、半年后、全栈角色、路径清单、能力象限 |
| 产品经理 | 思维模式、2B 互联网、贵人指路、30 岁、35 岁 |

### 6.6 页尾

- 品牌名与一句简短自我介绍；
- 视频号、公众号、作品入口；
- 可选联系方式；
- 版权年份；
- 隐私说明：网站不主动采集个人信息（若未来加入统计工具需要更新）。

## 7. 内容与卡片数据规范

为了便于后续持续维护，不应把所有内容直接散落写死在页面结构中。即使首版没有后台，也建议按统一内容对象组织。

### 7.1 系列内容

```yaml
title: 系列名称
slug: series-id
category: career | parenting | life
summary: 50-100 字简介
cover: 封面图片路径
platform: wechat | video-channel | website
url: 外部链接
status: published | updating | archived
featured: true | false
```

### 7.2 文章内容

```yaml
title: 文章标题
publishedAt: YYYY-MM-DD
summary: 50-80 字摘要
cover: 封面图片路径
url: 文章链接
tags: [标签一, 标签二]
featured: true | false
```

### 7.3 作品内容

```yaml
name: 作品名称
type: app | game | open-source | experiment
creator: tata | child | family
summary: 一句话说明
story: 创作背景
cover: 代表图片路径
demoUrl: 体验链接
sourceUrl: 源码链接（可选）
status: live | beta | building | archived
featured: true | false
```

## 8. 交互与跳转规则

### 8.1 外部链接

- 微信文章、合集和产品体验链接统一标注为外部链接；
- 桌面端在新标签页打开，避免用户丢失个人主页；
- 链接不可用时，不展示“立即体验”，改为“即将开放”；
- 每次上线前检查全部外链。

### 8.2 二维码

- 二维码旁必须有账号名称、平台名称和用途说明；
- 桌面端支持点击后放大；
- 移动端应提供“长按识别/保存图片”的明确提示；
- 若后续取得可直接打开微信内容的链接，应同时提供直接跳转按钮；
- 二维码原图不做强压缩，确保可识别。

### 8.3 页面动效

- 只使用轻量进入动画和卡片反馈；
- 不使用大面积粒子、赛博霓虹或高频滚动特效；
- 用户开启“减少动态效果”时应关闭非必要动画；
- 动效必须服务于阅读层级，不能抢夺内容注意力。

## 9. 视觉方向

### 9.1 设计关键词

**温暖、清醒、编辑感、真实作品、技术但不冰冷。**

### 9.2 建议视觉系统

- 主背景：温暖的米白或纸张白；
- 主文字：接近墨黑，不使用纯黑大面积铺底；
- 品牌强调色：提取当前小狗头像与视频号卡片中的暖橙色；
- 辅助色：三个主题可使用同一色系的不同深浅，避免三个互不相干的高饱和颜色；
- 字体：中文优先使用清晰的现代无衬线字体，标题可通过字重和排版建立编辑感；
- 图像：真实截图、真实作品和真实内容优先，不使用泛化的 AI 机器人素材；
- 装饰：可以使用细线、编号、页边注释等“个人研究笔记”语言。

### 9.3 三个主题的区分方式

不建议做成三个完全不同的视觉世界。建议通过以下轻量方式区分：

- 01 / 职场：结构化网格、方法卡片；
- 02 / 育儿：作品截图、过程照片、创作注释；
- 03 / 生活：文章排版、时间轴、年度记录。

统一头像、色彩、字体和卡片规范，保证它们始终属于同一个个人品牌。

## 10. 响应式、可访问性与性能

### 10.1 响应式

- 桌面端内容最大宽度建议为 1120～1200px；
- 移动端以单列阅读为主，作品卡片可横向滚动或纵向排列；
- 首屏在常见手机尺寸下应能看到主标题、简介和至少一个行动按钮；
- 二维码在移动端展示足够大，且不与其他二维码并排缩小。

### 10.2 可访问性

- 所有图片提供准确的替代文本；

## 17. 实施架构

### 17.1 应用结构

- 运行时：Node.js 20+；
- Web 框架：Express 5；
- 页面渲染：EJS 服务端模板；
- 前端交互：原生 JavaScript 与 CSS；
- 内容接口：Express JSON API；
- 身份验证：单管理员账号、scrypt 密码哈希、HttpOnly 签名会话 Cookie、CSRF Token；
- 本地内容存储：`data/site-content.json`；
- 生产内容存储：Neon PostgreSQL 的 JSONB 内容记录；
- 部署目标：Vercel Express Runtime 与 Fluid Compute。

### 17.2 前后台边界

```text
公开访问
└── GET /
    └── 从内容仓库读取已发布数据并服务端渲染

管理员
├── GET/POST /admin/login
├── GET /admin
├── GET /api/admin/content
└── PUT /api/admin/content
    ├── 校验管理员签名会话
    ├── 校验 CSRF Token
    ├── 校验完整内容结构
    └── 本地写入 JSON / 生产写入 PostgreSQL
```

### 17.3 生产持久化约束

Vercel 函数的本地文件系统不作为长期内容存储。生产环境如果没有配置 `DATABASE_URL`：

- 公开页面仍读取随代码发布的种子内容；
- 后台仍可登录和预览；
- 保存操作会被服务端明确拒绝；
- 页面不能显示虚假的“保存成功”。

生产发布前必须配置 `ADMIN_USERNAME`、`ADMIN_PASSWORD_HASH`、`AUTH_SECRET` 和 `DATABASE_URL`，并执行一次数据库初始化。

### 17.4 已实施视觉方向

- 人物首屏使用纸张感底色、暖橙品牌色与身份名片；
- 科技感由细网格、编号、轨道和微动效表达；
- 三个专题使用橙、绿、紫作为轻量区分；
- 不采用常见的深色霓虹 AI 模板，也不使用泛化机器人图片；
- 动效尊重系统的“减少动态效果”设置；
- 二维码使用真实素材，桌面端支持放大，移动端支持长按识别。
